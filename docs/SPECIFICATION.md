# SmartScan 仕様書

## 機能要件

- Windows 10/11 64-bitでカメラ映像をリアルタイム表示する。
- QRとOCRをユーザー操作なしで切り替える。
- QRをOCRより優先し、OCRは日本語と英数字を既定対象にする。
- 認識結果を画面表示し、クリップボードへコピーできる。
- 複数のカメラが接続されている場合、画面上で利用するカメラを切り替えられる。
- カメラ画像と結果は保存せず、初期化失敗は画面上に理由を表示する。

## 非機能要件

- UIプロセスでPaddleOCRを実行しない。
- 同時に複数のPaddleOCR推論を開始しない。
- PaddleOCRのCPUスレッド数を制限し、完了後にクールダウンを置く。
- QR検出は縮小画像を用い、設定されたフレーム間隔で実行する。
- QR探索中でもOCR初期化を待たない。
- QR検出後に保持時間を置き、モードのちらつきを防止する。
- ログはユーザーのローカル領域へローテーション保存し、画像と認識文字列は記録しない。
- UIフレーム処理を監視し、3秒以上の停滞時は処理段階をログへ記録する。
- カメラ探索はUIをブロックしないワーカースレッドで行う。
- カメラフレーム取得は専用スレッドで行い、UIスレッドはブロッキング読取を行わない。
- UIタイマーは設定FPSで高精度駆動し、実測プレビューFPSを画面とログへ表示する。
- 新着フレームの確認は設定FPSの4倍の周期で行い、カメラの不均一な到着間隔による取りこぼしを防止する。
- QR検出とOpenVINOゲート推論は単一の解析ワーカーで行い、UIスレッドをブロックしない。
- 解析結果には取得元カメラを関連付け、カメラ切替後に旧カメラの結果を破棄する。
- モード・スコア表示は値の変化時だけ更新し、フレーム配列は取得側からUI側へ参照で受け渡す。
- プレビュー画像はOpenCV側で表示寸法へ変換し、Qt側での追加色変換と拡縮を行わない。
- プレビュー表示幅は設定で制限でき、認識処理にはカメラ本来の解像度を使用する。
- WindowsのカメラバックエンドはMedia Foundationを優先し、失敗時はDirectShowへフォールバックする。

## 処理構成

```text
Webカメラ -> OpenCV -> QRCodeDetector ---------> QR結果
                   |
                   +-> OpenVINO edge gate -> PaddleOCR process -> OCR結果
```

OpenVINOモデルは起動時に演算グラフから構築する。Sobel X/Y畳み込みと絶対値平均によりエッジ量を返し、重いPaddleOCRを実行する頻度を制御する。

## 対象外

QR以外のバーコード、手書き専用認識、履歴の永続保存、クラウド送信、CUDAの自動構成。

## 配布形式

PyInstallerの`onedir`形式を標準とする。専用specでPaddlePaddle、PaddleOCR/PaddleX、OpenVINO、PySide6の動的モジュール・データ・ネイティブライブラリを収集する。設定ファイルはEXE外部へ配置し、OCRモデルはユーザーごとのローカルキャッシュへ保存する。
